# Software Architecture

Software architecture provides structure for solving business problems.

Architecture should improve clarity, maintainability, and adaptability.

## Principles

- Start with a Modular Monolith.
- Prefer Hexagonal Architecture by default.
- Organize projects using Screaming Architecture.
- Introduce Event-Driven Architecture when the domain requires it.
- Extract microservices only when they provide clear business value.

## Decision Making

Architecture should always be driven by the domain.

Patterns, frameworks, and architectural styles are selected because they solve problems—not because they are popular.

Architecture evolves continuously through experience.
